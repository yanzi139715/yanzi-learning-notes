一个 React Native 手机 App 给字号设了放大上限（1.15 倍）。把安卓系统字号调到 2.0 后：字只大了一点，但行距忽大忽小，文字被上下裁掉一半，带阴影的大数字下面露出像省略号一样的残影，多行大标题叠在一起。同样的设置在 iPhone 上一切正常。

## 原因

以下来自安卓模拟器（Android 15）上逐页截图对比（事实）：

- 在当时使用的 React Native 0.86 中，安卓端的 `maxFontSizeMultiplier` 只限制字号；行高（`lineHeight`）和字距（`letterSpacing`）仍然按系统字号原样换算，不受上限约束。
- Android 14 起，系统字号的换算是非线性的：字号越大，放大比例越小。
- 两者叠加的结果：13 号字只放大了 15%，但 20 的行高却被换算成约 34。行盒和字形对不上，于是出现截字、错位和残影。

还踩过两条弯路：

- “先把行高和字距按系统倍数除回去”行不通。因为换算是非线性的，除不准，反而让两行标题叠到一起。
- “让每个文字组件订阅窗口尺寸变化”会在 App 运行中修改系统字号时引起原生崩溃。

## 怎么做

- **统一的文字包装组件**。安卓系统字号大于 1 时，关闭原生字号缩放（`allowFontScaling={false}`），自己按 `k = min(系统字号倍数, 上限)` 线性放大字号、行高、字距三者。嵌套的文字不要重复放大。
- **渲染时现读系统字号**，不要让每个文字组件都订阅窗口尺寸。
- **窄屏收回**。屏幕宽度很窄（大约不到 360）时，把倍数收回到 1，避免挤到截字。
- **内嵌网页单独处理**。WebView 加 `textZoom={100}`，避免安卓只放大网页里的字、不放大原生按钮。
- **加回归测试**：线性放大、嵌套不重复放大、窄屏收回、包装组件不订阅窗口尺寸。

修改后，安卓在大字号下和 iPhone 一样按比例放大，三十多屏截图没有截字和重叠。

## 适用范围与失效条件

适用于 React Native 安卓端设置了字号上限、或依赖系统字号的 App。其他框架如果也是只限字号、不限行高，值得按同样思路检查。

如果以后的 React Native 版本让行高和字距也遵守字号上限，或者 Android 改回线性换算，就可以退回原生缩放。

**未知**：窄屏收回对 iOS 的影响没有在 iOS 模拟器上实测。
