一个单文件 HTML 原型，之前在本机地址上能打开，隔了一阵再刷新，浏览器提示连接被拒绝。页面文件还在，内容也没坏。

查下来：这个地址已经没有任何程序在提供服务了。

## 原因

当时用的是某个工具自带的临时预览脚本。它每分钟检查一次，超过 30 分钟没人访问，就记一条“闲置停止”，然后自己退出。

所以页面没坏，网络和代理也没问题，只是这个预览服务本来就只打算临时用一下。

## 排查顺序

从外往里查，少走弯路：

1. 访问一下地址，确认到底通不通。
2. 看端口上有没有程序在监听。
3. 找服务自己的状态记录或日志，看它是不是主动退出的。
4. 看服务的代码，有没有闲置超时之类的设置。
5. 最后才去看页面文件。

没搞清楚服务为什么停之前，先别动页面代码或代理设置。

## 怎么恢复

端口空着的话，用 Python 自带的静态服务在原来的端口重新开起来：

```bash
mkdir -p preview && ln -sf ../prototype.html preview/index.html
python3 -m http.server 8080 --bind 127.0.0.1 --directory preview
```

注意几点：

- 只绑定 `127.0.0.1`，也就是只有本机能访问。别为了方便开放给整个网络。
- 服务目录里只放要预览的文件，别把整个工作目录都暴露出去。
- 它不会自动刷新，改完页面要手动刷新浏览器。

恢复后，原地址能正常打开，内容一致；访问目录外的文件会返回 404。

## 适用情况

适合单个 HTML 原型因为临时预览服务退出而打不开的情况。

电脑重启、进程被关、端口被占、文件被挪走，都会让它再次打不开。多文件项目、需要后端或热更新的应用，用各自的开发服务器。要给别人访问，需要另外考虑托管和权限，不要直接放开监听范围。新的启动方式没有做长时间测试，只确认了它没有闲置退出的设定。
