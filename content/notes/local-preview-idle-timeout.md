一个单文件 HTML 原型，之前在本机地址上能正常打开；隔了一段时间再刷新，浏览器提示连接被拒绝。磁盘上的页面文件完好无损。

## 现象

- 本机地址的 HTTP 请求直接失败。
- 检查端口监听，没有任何进程在听这个端口。
- 页面文件本身可以正常读取。

## 原因

**事实：**这次用来提供预览的是一个工具附带的临时预览脚本。它有闲置退出策略：每分钟检查一次，超过 30 分钟没有访问就写下一条“因闲置停止”的状态记录，然后停止监听。

所以“打不开”不是页面坏了，也不是代理或网络问题，而是这个服务本来就只打算陪一次会话，不是长期托管。

## 排查顺序

按从外到里的顺序查，能少走很多弯路：

1. 用 HTTP 请求确认地址到底通不通。
2. 查端口有没有进程在监听。
3. 找服务自己写的状态文件或日志，看它是不是主动退出、为什么退出。
4. 读服务的生命周期代码，确认有没有闲置超时之类的设定。
5. 最后才检查页面文件本身是否完整。

在确认服务生命周期之前，不要先去改页面代码或系统代理设置。

## 怎么恢复

确认端口空闲后，用系统自带的 Python 标准库静态服务在同一端口重新提供页面：

```bash
mkdir -p preview && ln -sf ../prototype.html preview/index.html
python3 -m http.server 8080 --bind 127.0.0.1 --directory preview
```

几个要点：

- 只监听本机回环地址 `127.0.0.1`，不要为了方便改成监听所有网卡。
- 服务根目录只放要预览的文件，不要把整个工作目录变成可浏览目录。
- 这种服务没有自动刷新，改完页面需要手动刷新浏览器。

恢复后，原地址返回 HTTP 200、内容与目标页面一致，请求目录外的文件返回 404。

## 适用范围与失效条件

适用于被临时预览服务生命周期中断的单文件本地原型。

以下情况仍会再次打不开：电脑重启、进程被结束、端口被占用、链接的目标文件被移动。多文件工程、需要后端接口或热更新的应用，应该用各自的开发服务器；需要别人从外部访问时，要另外设计托管和访问权限，而不是扩大监听范围。

**未验证：**没有做长时间的耐久测试，只确认了新启动方式不再包含原来的闲置退出逻辑。
