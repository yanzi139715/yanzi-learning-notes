同一个 git 仓库里同时开着几个 AI 编程会话，各干各的活。结果出现了两次“混提交”：

1. 某个会话只 `git add` 了自己改的文件，再 `git commit`，提交里却多出十几个其他会话的文件。
2. 改用 `git commit -- 某文件` 想“只提交这一个文件”，结果把同一个文件里别人还没提交的删改也一起带了进去。

另外，两个会话同时编译 iOS 时，`xcodebuild` 报 `database is locked`。

## 原因

以下三点都是 git 和 Xcode 的既有行为（事实）：

- **一个工作区只有一个暂存区（index）。**所有在这个目录里工作的会话共用它。别的会话已经 `git add` 的内容，任何人执行不带路径的 `git commit` 都会一起提交。
- **`git commit -- 路径` 提交的是该路径在工作区里的当前内容**，而不是你暂存的那部分。同一个文件里别人的未提交改动会被一起打包。
- **Xcode 的构建数据库同一时间只允许一个构建写入**，并行编译会互相锁住。

## 怎么做

1. 提交前先看暂存区里都有什么：

   ```bash
   git status --short
   ```

   看到不是自己的已暂存文件，就不要直接不带路径地提交。

2. 和别人改同一个文件（比如更新日志）时，只暂存自己那几块改动：

   ```bash
   git diff -U3 -- CHANGELOG.md > mine.patch
   # 手动编辑 mine.patch，只留下自己的改动块
   git apply --cached mine.patch
   git commit
   ```

3. 已经提交错了：

   ```bash
   git reset --soft HEAD~1
   git restore --staged <别人的文件>
   # 重新提交自己的部分
   ```

   然后告诉对方会话，请它检查自己的暂存状态。

4. 主工作区被别人做到一半的改动卡住（编译不过、拉取被拒）时，用 `git worktree add` 开一个独立目录单独编译和验证。

5. 原生构建开始前，先看看有没有别人正在编：

   ```bash
   pgrep -f xcodebuild
   ```

   有的话错开时间。

按第 2、3 步重新提交后，提交里只剩本会话自己的改动。

## 适用范围与失效条件

适用于多个 AI 会话或多个终端共用同一个工作区的仓库，尤其是有大家都会改的公共文件（更新日志、索引、配置）的项目。

如果每个会话都在自己的 git worktree 或独立克隆里工作，暂存区就不再共享，前半部分问题不会出现。
